# SecurityOps 2.0 — Module implementation evidence

**Checked:** 2026-11-16, Phase 11 local worktree. This inventory maps active UI/API/database paths and available automated evidence. A row is not a full acceptance of every product requirement. The full route-by-route role/object matrix and deployment/device/provider acceptance remain open.

## Active architecture

The root `package.json` starts the Vite frontend and `frontend/backend` Node/TypeScript service. `frontend/backend/package.json` builds `src/server.ts`; `frontend/deploy/Dockerfile.backend` builds and runs that service, and `docker-compose.production.yml` runs its one-shot migration container separately. The active database migration path is `frontend/backend/src/migrations`, currently through 042.

Python files in `frontend/backend/*.py`, `frontend/alembic`, and `frontend/tests/test_*.py` remain in the repository as a separate historical implementation path. They are not selected by the current npm scripts or production Dockerfile. The current successful Jest/Vitest runs do not validate that Python path. No speculative backend rewrite or removal was performed.
